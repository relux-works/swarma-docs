# Большие файлы и память сети

Алиса записала видео о чаепитии. Оно не поместится ни в какую транзакцию, поэтому файл живёт в сети BitTorrent: это обычная раздача, где участники передают части файла друг другу. В цепочку попадает короткая ссылка magnet или хэш. Обычная ссылка занимает 60 байт. Клиент скачивает файл и сверяет его с хэшем: подменить содержимое нельзя.

Распространение устроено так же, как и у доверенностей: документ лежит вне цепочки, его отпечаток в цепочке. Страница, Markdown или видео может быть чем угодно, а вся логика проверки одна. Клиент показывает скачанный Markdown и HTML так, чтобы они не могли выполнить чужой код.

Кто раздаёт файл? Сначала автор. Затем те, кому интересно: популярное видео раздают многие, поэтому оно живёт долго. Лайк может включать раздачу по настройке клиента, хотя сам по себе лайк места на диске не занимает. Кому нужно надёжнее, платит узлу за хранение на срок: это услуга рынка узлов с названным сроком и числом копий.

Хранение здесь вероятностное, а не гарантированное. То, что важно многим, скорее всего сохранится, а остальное может потеряться, и это приемлемо. Но популярность не даёт гарантии: в большом исследовании 2009-2010 годов (Kaune и соавторы, 46 тысяч раздач) 38% раздач стали недоступны в первый же месяц, причём некоторые раздачи без полных копий всё равно завершались из разрозненных частей. Поэтому клиент говорит честно: файл есть у меня, файл доступен у таких-то узлов на такое-то время, файл доступен частично, файл утрачен и осталась только ссылка.

Браузер работает с BitTorrent через WebTorrent, поверх WebRTC. Обычная веб-страница не имеет сырых сокетов, поэтому ей нужен раздающий узел с поддержкой WebRTC и служба сигнализации. На настольном клиенте работает обычная библиотека libtorrent. Закрытые файлы из Swarma Talk шифруются до раздачи и публичными не становятся.

Вывод простой: хэш в цепочке сохраняет доказательство, а хранить файл должен кто-то живой. Если видео Алисы важно ей самой, ей стоит оплатить хранение.
