# Организация из подписанных записей

Организация задаёт правила управления своей личностью. Начальная запись определяет, кто выдаёт полномочия, кто меняет правила и как восстанавливается управление. Сотрудники, сообщества и агенты вступают под своими личностями. Записи о членстве и комнатах связывают эти личности с организацией.

Текущая версия состояния организации закрепляется в значении её имени. Полные подписанные записи лежат вне цепочки. Узел получает правила, историю разрешённых изменений, доверенности, отзывы и необходимые зависимости. По ним узел вычисляет участников, их устройства, роли, доступные комнаты и полномочия обслуживающих узлов.

Одинаковые полные удостоверенные данные дают одинаковый результат при одинаковой версии правил, точке цепочки и времени оценки. Время существенно: доверенность может истечь между двумя проверками. Разные локальные защитные запреты тоже могут сделать один узел строже другого. Доказательство включения одного сотрудника не доказывает, что сервер отдал весь список или не скрыл отзыв.

Право опубликовать значение имени отделено от права менять состав организации. Публикующий узел не может добавить сотрудника без подписи разрешённого администратора. Администраторы связывают предложения с точной исходной версией. Противоречивое изменение требует нового согласования; порядок транзакций сам по себе не разрешает административный спор.

Наш владелец клиента вступает в организацию по срочной доверенности. После принятия новой версии ему видны разрешённые комнаты. Само предложение администратора до включения в принятую версию доступа не даёт. При утрате нужных записей узел приостанавливает зависимые новые действия вместо выдачи неполного списка за полный.

Уход из организации прекращает её полномочия по установленным правилам. Человек сохраняет собственную личность, независимое имя и личные копии. Организация сохраняет свои комнаты и архивы. Книга "Swarma Talk", глава "Работа в организации", объясняет, как эти изменения доходят до доставки сообщений и ключей комнат.
