# Проблема

Пока агент один, модель для него выбирают один раз и забывают. Когда агентов становится много, выбор модели превращается в постоянную работу: каждую задачу нужно отправить на подходящую конфигурацию, и каждая ошибка стоит либо качества, либо денег. Владелец роя назвал пять болей, и роутер отвечает на каждую.

## Ручные правила

Сегодня правила выбора живут в конфигурации доски и в головах оркестраторов: «разработчик по умолчанию на Sol high», «ревью на Astra medium», «Claude только резервом». Правила копятся, противоречат друг другу и устаревают каждый раз, когда выходит новая модель. Никто не видит, почему для конкретной задачи выбрано именно это, и никто не может проверить, было ли правило хорошим. ⟦работает сегодня⟧

Роутер переводит правила в данные: постоянные правила оператора с областью действия, порядок предпочтений и замеры. Каждое применённое правило печатается с идентификатором, источником и обоснованием и сохраняется в решении.

## Усилие не по задаче

Уровень рассуждений — самая дорогая и самая забываемая ручка. Переименовать файл на `xhigh` — сжечь квоту. Ревьюить критичное изменение на `low` — пропустить дефект. Оркестратор, который запускает десятки задач в день, ставит одно и то же усилие по привычке.

Роутер выбирает усилие вместе с моделью: у каждой сложности есть минимальный уровень качества, и самое дешёвое усилие, которое до него дотягивается, выигрывает в экономном режиме.

## Качество против цены

Конфигурации отличаются по цене в разы, а по качеству — часто в пределах шума бенчмарка. На уровне `high` пять наших основных конфигураций статистически неразличимы на публичной доске Bug Hunt, а стоимость прогона по прайсу отличается в 6–15 раз. Без явного взгляда «качество против цены» рой либо переплачивает, либо экономит не там.

Роутер держит этот взгляд явно: отбирает лучших по Парето и выбирает среди них по режиму бюджета, который задаёт владелец.

## Сильнейшая модель для трудного и деликатного

Есть задачи, на которых экономить нельзя: критичное ревью, изменение формата данных, безопасность. Для них владелец хочет сильнейшую доступную конфигурацию, даже если для задачи закреплена другая. Это решение R164: для трудных и критичных задач планка уровня сильнее ручной закрепки. ⟦решено⟧

## Параллельный поиск

Исследовательскую задачу выгодно отдать сразу нескольким моделям разных семейств: они ошибаются по-разному, и сводка их ответов надёжнее любого одного. Роутер умеет выбрать до трёх (в режиме burn — до четырёх) конфигураций уровня A и выше из разных семейств и запустить их одной командой (`--fanout`). Сводку ответов он пока не делает. ⟦работает сегодня⟧

## Чего мы не хотим

Мы не хотим ещё одного агента, который думает над тем, на каком агенте запустить задачу. Такой агент сам стоит денег и времени, сам ошибается, и его выбор нельзя ни повторить, ни объяснить. Мы не хотим прокси перед API провайдера и не хотим, чтобы выбор модели обходил ограничения доски. Роутер — отдельный, проверяемый шаг подготовки запуска, а не ещё один участник роя. ⟦решено⟧
