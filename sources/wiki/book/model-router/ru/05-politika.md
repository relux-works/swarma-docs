# Политика: бюджеты и постоянные правила

Политика — это то, что владелец решает один раз, а роутер применяет к каждой задаче. Она лежит в файле `~/.curator/routing.toml` (или передаётся флагом `--policy`), читается строго и замораживается в каждом решении.

## Файл политики

```toml
schema_version = "recommend-policy-v1"
mode = "select"
budget_mode = "balanced"
allow_metered = false
catalog_overlay = "/home/me/.curator/catalog-overlay.json"

[difficulties.hard]
minimum_tier = "A"
objective = "quality"
```

- Неизвестное поле или неверное значение — отказ, а не молчаливое умолчание.
- Отсутствующий неявный файл означает встроенные умолчания; явно указанный и отсутствующий — отказ.
- Пороги ступеней задаются отдельно для индексов (`tier_edges`) и для замеров ревью (`review_tier_edges`), потому что это разные шкалы.

## Постоянные правила

Правило — это решение владельца, записанное как данные. У каждого правила есть идентификатор, источник (например, номер решения в канале), обоснование и область действия. ⟦работает сегодня⟧

| Вид правила | Пример |
| --- | --- |
| исключить семейство автора на ревью | ревьюер не из той же семьи, что разработчик (`--producer-family`) |
| исключить конфигурацию | `--exclude runtime/model` или правило в файле |
| закрепка на машине | на этой машине обычное ревью идёт на Astra medium |
| предпочтение среды | среди лучших по качеству предпочесть Codex |
| правило истории | для конкретной story — своя закрепка |

Область действия задаётся списками `when.difficulty` и `when.sensitivity`. Правило без списков действует всегда. Пропущенное правило называет в объяснении признак, по которому оно не подошло, так что «почему не сработало» видно сразу.

Правила только отсеивают уже допущенных кандидатов. Они никогда не обходят планку сложности и не перебивают явную закрепку вызывающего.

## Решение R164

Для трудных и критичных задач нужна сильнейшая подходящая конфигурация, даже если на машине закреплён другой ревьюер. Владелец решил это так: закрепка ревьюера на машине действует только для trivial, routine и standard; для hard и critical роутер ранжирует по качеству и среди лучших по качеству предпочитает Codex. ⟦решено⟧ ⟦работает сегодня⟧

## Режимы бюджета

Три режима из главы 3 — это одна настройка политики, которую можно переопределить на одно решение флагом `--budget`. Режим записывается в решение и входит в его идентификатор. Автоматический выбор режима по остатку квоты отложен: значение `auto` отклоняется. ⟦решено⟧

## Квоты

`cmr usage refresh` читает остаток подписок через официальные интерфейсы сред (планы чтения `providerquota` из agents-management) и кэширует его. Роутер использует остаток только для порядка: в режиме burn внутри равного качества он тратит подписку, у которой больше всего сгорающего запаса. Неизвестный или устаревший остаток нейтрален: он не наказывает и не поощряет кандидата. Роутер не ведёт своего счётчика квот и ничего не резервирует. ⟦работает сегодня⟧
