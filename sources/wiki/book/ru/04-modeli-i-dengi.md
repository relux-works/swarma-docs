# Модели и деньги

## Потребности вместо моделей

Закоммиченный файл не должен ломаться у коллеги с другими harness'ами. Поэтому роли пишут потребности, а не id моделей и не effort: `require` — жёсткое требование, `prefer` — только порядок кандидатов. Словарь один: `publisher`, `family`, `capabilities`, `context_window`, `reasoning`, `local`, `not_same_publisher_as` и скорость — `pp`, `tg`, `ttft`. ⟦решено⟧

```json
"reviewer": { "needs": {
  "require": { "not_same_publisher_as": "developer", "reasoning": true },
  "prefer":  { "publisher": ["anthropic"], "tg": { "min": 50 } } } }
```

- **Независимость** проверяется по происхождению run'а, который сделал проверяемую работу, а не по чьим-то настройкам. ⟦решено⟧
- **Скорость** берётся из лучшего факта: замер на этой машине, потом типичный диапазон из реестра, иначе «неизвестно», и требование не выполнено. ⟦решено⟧
- **Effort выбирает оператор**, а проект может задать нижнюю планку для роли по шкале `minimal < low < medium < high < xhigh < max`. ⟦решено⟧

## Файлы оператора

Всё, что принадлежит одному человеку и одной машине, живёт в личных TOML-файлах в `~/.curator/` и никогда не коммитится: `models.toml` (привязки ролей, допуски, окна, постоянные ответы), `runtimes.toml` (runtime'ы и мощность машины), `engines.toml` (локальные движки), `network.toml` (сетевые профили) и `curator.toml` (настройки Curator и допущенные источники скиллов). ⟦решено⟧

```toml
[bindings]
"dev-cycle/developer" = { run = "codex/gpt-6-luna", effort = "max" }
"@reviewer"           = { run = ["claude/claude-opus-5-5", "codex/*"], effort = "medium..high" }

[allow]
models  = ["codex/*", "claude/claude-opus-5-5", "local/qwen3.6-27b"]
billing = ["subscription", "local"]

[windows]
"local/qwen3.6-27b" = "22:00-07:00"
```

Ключи идут от частного к общему: `<playbook>/<роль>`, `*/<роль>`, `@<способность>`. Резолвер берёт первого кандидата, который допущен, доступен и подходит роли, и записывает, почему отпали остальные. ⟦решено⟧ Файлы правят команды `curator models|runtimes|inference engines|network|sources`: с бэкапом, атомарно, без секретов и без расширения допуска изнутри агентской сессии. ⟦решено⟧ Команд ещё нет, а их имена пересматриваются вместе со всем CLI (глава 13). ⟦предложено⟧

## Деньги

- **Способы оплаты**: `subscription`, `local` и `metered`, то есть плата за токены. Без `models.toml` автоматический выбор `metered` не берёт никогда, а runtime с неизвестным способом оплаты считается `metered`. ⟦решено⟧
- **Платить за токены разрешает только собственный файл оператора**, и только после его подтверждения с присутствием. Проект может способы оплаты только сужать. ⟦решено⟧
- **Всё, что расширяет допуск, ждёт подтверждения**: новая модель, оплата за токены, постоянный ответ, более широкое окно, новый runtime, неизвестный источник скиллов. Сужение действует сразу. ⟦решено⟧
- **Проект может жёстко ограничить модели**, например по политике безопасности заказчика: `policy.data.models` с шаблонами allow и deny. Сегодняшние `spawn.ceilings` переезжают туда. ⟦решено⟧

Итоговый выбор — пересечение: допуск проекта ∩ допуск оператора ∩ то, что есть на машине ∩ потребности роли. ⟦решено⟧

## Когда потребность не выполнена

`on_unmet` бывает `block` (по умолчанию), `fallback`, `ask` и `degrade`. ⟦решено⟧

- **`ask`** — человек одобряет временное исключение только для своих run'ов, в пределах поддерева и срока, и исключение видно на борде.
- **Постоянный ответ** — ответ на `ask` заранее, в `[answers]` файла `models.toml`, можно бессрочный. Каждое применение видно на борде, раз в месяц ответы проходят ревью, а неподтверждённый ответ перестаёт действовать. Проект может запретить их совсем.
- **`degrade`** запускает лучшее доступное и добавляет ревью, но не для независимости: лишние ревью от того же издателя её не вернут.

## Где и на чём запускать

- **Launch profiles, веха M4.** Проект говорит: «разработчики могут работать на `team-local-qwen`». На Mac оператора личный файл уточняет, что это codex с llama.cpp на `127.0.0.1:8080` и моделью Qwen, только с 22:00 до 07:00. У коллеги это имя ведёт на его сервер или отсутствует, и тогда его пропускают. ⟦решено⟧
- **Локальные модели, веха M5a.** `curator-inference-manager` держит движки готовыми (`status|ensure|release|stop`), а доступность движка — два факта: `ready` и `ensurable`. ⟦решено⟧ Запись этого решения, Decision 0020, ещё не написана. ⟦открыто⟧
- **Доступность, веха M5b**: один запрос «что может работать сейчас, по профилю» к агрегатору в agents-management. ⟦решено⟧ Спеки пока нет. ⟦открыто⟧
- **Сетевые профили, веха M7**: каждый запуск ходит в сеть через свой прокси, не трогая соседей. Это кооперативная маршрутизация, а не песочница. ⟦решено⟧
- **Маршрутизация, веха M8.** `curator-model-router` выбирает среди уже допущенных кандидатов и записывает почему. На вопросы «допущено?», «совместимо?», «подходит?» и «доступно сейчас?» отвечают разные хозяева, и высокая оценка никогда не перебивает остальные ответы. LLM не обязателен: Jev или структурированный LLM — заменяемые оценщики. ⟦решено⟧
