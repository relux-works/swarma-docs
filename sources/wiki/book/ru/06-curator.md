# Curator: скиллы, профили, оверлеи, аудиты

Curator — менеджер окружения агентов: инструкции, скиллы, команды и MCP-серверы агент получает через него. Репозиторий публичный, последний тег `v0.15.0-rc.1`; протокол — `curator-spec`, тег `v1.0.0-rc.12`. ⟦работает сегодня⟧

## Скиллы и аудит

- **Скилл — пакет**: `SKILL.md` и, по желанию, `agents/`, `references/`, `.skill_triggers/`, `assets/`, `templates/`, `examples/`, `data/`. К агенту попадают только эти корни. ⟦работает сегодня⟧
- **Проект объявляет скиллы в `Skillfile.json`**, Curator ставит их и фиксирует версии в lock. Команды скилла становятся глобальными шимами с одним владельцем на имя и собираются из проверенного исходника. Зависимость в режиме `full` кладёт контекст скилла в сессии, а в режиме `runtime` включает только его команды. ⟦работает сегодня⟧
- **Skillfile schema 2** — источники-репозитории и выбор скиллов по папкам — уже есть за флагом; выпустить её — часть задания для Curator. ⟦решено⟧
- **Аудит.** `curator audit` проверяет пакет и публикует подписанную запись, которая совпадает с артефактом по хэшу содержимого, так что копия из зеркала совпадает тоже. ⟦работает сегодня⟧ Сервис реестра `curator-skill-registry` с журналом прозрачности в реализации, релизов нет. ⟦работает сегодня⟧
- **Политика**: агенты сами ставят проверенные скиллы, неизвестные источники по умолчанию отвергаются, а рекомендованный путь — отправить скилл на аудит. ⟦решено⟧ Пакет с подписанной записью аудита ставится по ней, без долгого локального аудита, и установщик тоже подписан: скомпрометированный установщик всё равно пропустил бы любую локальную проверку. ⟦предложено⟧

## Профили и оверлеи

- **Профиль** — корневой контекстный пакет, его `Skillfile.json` и объявления MCP, закреплённые в lock. Curator ставит его из git по тегу, диапазону или ревизии, в том числе из подпапки; без версии берётся последняя (`--range latest`). Для каждой пары «профиль × harness» собирается свой управляемый дом (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`). ⟦работает сегодня⟧
- **Профили ролей вместо папок проекта**: каждый run стартует с профилем своей роли, «спящие» скиллы отменены, задачи #91 закрыты. ⟦решено⟧
- **Профиль — единица установки**: пакет Кипера несёт профиль `apiary` и профили системных ролей. ⟦предложено⟧ Нести ли профили ролей в пакете процесса, не решено. ⟦открыто⟧
- **Оверлеи машины** — git-репозитории или папки с весами, объявляемые только в конфигурации машины. ⟦работает сегодня⟧ Для пасеки порядок такой: профиль пакета, потом оверлей процесса, потом оверлей оператора с персоной и памятью; закреплённые модули пакета не убрать. ⟦предложено⟧

## `curator run` и одна точка сборки

- **`curator run` — единственная дверь для человека**: окружение Curator плюс план запуска из agents-management. Лаунчер получил первый тег `v0.1.0`; запуск без учёта работает, а учёт сессий ждёт session host. ⟦работает сегодня⟧
- **Decision 0021**: с интеграцией ax сессия с рождения живёт в session host, `task-board claude|codex` становятся алиасами, `--untracked` даёт прямой запуск. Оператор решил, в curator-spec запись пока proposed. ⟦решено⟧
- **Decision 0019**: запуски собираются только в модуле agents-management, иначе копии расходятся, и один забытый `--strict-mcp-config` пускает в дочерний run чужие MCP-серверы. ⟦решено⟧
