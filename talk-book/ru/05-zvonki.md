# Звонки

Алиса звонит Бобу. Приглашение идёт по уже защищённому каналу их контакта, поэтому посторонний не может незаметно притвориться Бобом. Клиент проверяет связь приглашения с параметрами устанавливаемого защищённого медиасоединения. Сам разговор идёт по другому пути, потому что голосу нужна низкая задержка.

Для передачи голоса и видео мы берём WebRTC, существующий стек с шифрованием и подавлением эха. Сначала клиенты пытаются соединиться напрямую. Большинство устройств сидит за маршрутизаторами, которые не пропускают входящие соединения, и здесь помогает ICE: клиенты перебирают возможные пути. Сервер STUN подсказывает клиенту его внешний адрес. Если прямого пути нет, например в корпоративной сети со строгими правилами, разговор идёт через сервер TURN, который пересылает зашифрованный поток.

Прямой звонок раскрывает собеседникам адреса друг друга. Режим только через TURN скрывает их друг от друга: клиент запрещает прямые ICE-кандидаты и прямые пути соединения. Адреса и объём трафика при этом видит сам TURN. Содержимое он не читает.

Пересылка стоит денег. Расчёт для постоянного потока в каждую сторону, без служебных данных, повторов и смены способа сжатия: при 64 кбит/с разговор через такой сервер даёт около 58 МБ в час на выходе, а видео по 1 Мбит/с около 900 МБ. Тысяча одновременных видеозвонков это примерно 2 Гбит/с. Этот счёт кто-то оплачивает: на старте мы, затем подписчики этой услуги или организация для своих сотрудников.

Трафик пересылают только узлы, которые сами на это согласились: провайдеры и организации. Компания, которая держит постоянно работающий узел для своих людей, тем самым делает всю сеть менее зависимой от любого одного оператора.

## Групповые звонки

При разговоре нескольких человек прямые соединения быстро перегружают канал, поэтому поток идёт через сервер, который раздаёт его участникам. В Nostr для таких голосовых и видеокомнат уже описана связка с LiveKit. Если такому серверу не доверять, шифрование добавляется на уровне участников, и это отдельный стандарт SFrame. Без него сервер видит содержимое. Клиент показывает, какой режим включён.

Клиент показывает "соединено" только тогда, когда голос идёт в обе стороны. Подтверждённое приглашение этого не означает.
