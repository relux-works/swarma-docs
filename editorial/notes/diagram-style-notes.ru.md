# Единый стиль диаграмм: исследование и пилот

Задача TASK-261025-e493tn, 25 октября 2026 года. Направление владельца: все диаграммы платформы выглядят как образцы, чисто и одинаково; дизайн-система покрывает все случаи платформы; утилиты и скиллы для диаграмм можно менять. Образцы (три снимка с oberheide.org) приватные и служат только для стиля; в репозиторий они не копируются, здесь описаны только их черты.

Итог: выбран собственный маленький генератор `scripts/diagram-kit/` (Python, стандартная библиотека, Graphviz `dot` для авторасстановки графов). Правила стиля записаны в `editorial/diagram-style.ru.md`, тема в `scripts/diagram-kit/theme.toml`. Перерисованы четыре пилота с суффиксом `-v2`; старые рисунки, текст книги и PDF не тронуты.

## 2. Сравнение инструментов

Пробник для всех инструментов один: команда с телефона (оператор, Signer в границе телефона, Matrix, ворота агента, пять шагов, протокол на одной паре, возврат к оператору). Каждый рендер проверен глазами в PNG и в настоящем конвейере книги: SVG вставлен в HTML и пропущен через WeasyPrint 70.0, страница PDF растрирована `pdftoppm`. Рабочие файлы пробника лежат в рабочем каталоге задачи вне репозитория и не публикуются.

| Критерий | D2 0.9.0 | PlantUML 1.2026.6 со своим `<style>` | Mermaid CLI 12.0.0 | Свой генератор (diagram-kit) |
| --- | --- | --- | --- | --- |
| Близость к образцам без ручной правки | средняя: цвета, скругления и пунктир задаются; подписи стрелок лежат на линии, не снаружи; протокола между парой стрелок нет; блоки разной ширины; возврат петлёй | низкая: Graphviz поставил оператора вниз, стрелки кривые, текст выровнен влево | низкая: жирное в `**…**` не работает без HTML-меток, тени, фон у подписей, раскладка разбросана | высокая: парные стрелки, подписи снаружи, протокол между ними, номера в кружках, пунктирные границы с разрядкой |
| Одна тема на всё | да: классы в импортируемом `theme.d2` | да: `!include` файла со `<style>` | частично: `themeVariables` плюс `classDef` в каждом файле | да: `theme.toml`; исходник не может переопределить цвета (проверено тестом) |
| Детерминированный текст, читаемый diff | SVG одинаков между запусками, но 75 КБ, в нём base64 трёх встроенных шрифтов | одинаков, 8,5 КБ | одинаков, 22,7 КБ, CSS со сгенерированными классами | одинаков (тест), 6,2 КБ, комментарий на каждый элемент |
| Офлайн, macOS и Linux | да, один бинарник; PNG свой, без браузера | да, Java и Graphviz | только с headless Chrome через puppeteer | да: Python 3.11+, Graphviz только для `graph`, `rsvg-convert` для PNG |
| Русский текст, PT Sans и PT Mono | да, но TTF приходится вынимать из системных TTC; кружков с цифрами в PT Sans нет, берётся другой шрифт | да | да | да; кружки рисуются фигурой; `→` автоматически из PT Mono |
| SVG в WeasyPrint (книга) | ломается: вместо текста чёрные полосы | рисуется; разрядка, сделанная пробелами, схлопывается | подписи узлов пропадают целиком | рисуется верно, включая разрядку |
| Вертикальная последовательность с парными стрелками | нет управления сторонами подписей | нет | нет | да, раскладка `stack` |
| Пунктирные границы с подписью прописными с разрядкой | пунктир и прописные есть, разрядки нет | разрядка только пробелами | нет разрядки и скругления | да |
| Время на рисунок | 0,06 с | 1,9 с | 1,6 с | 0,07 с |
| Цена | чужой проект, правка раскладки невозможна | текущий инструмент; стиль упирается в Graphviz | браузер в цепочке сборки | свой код: генератор около 1050 строк и 8 тестов; качество `graph` ограничено `dot`; проводов схем нет |

Выбор: свой генератор. Только он даёт черты образцов без ручной правки и при этом проходит через WeasyPrint, которым собирается книга. D2 был вторым кандидатом, но его SVG в книге не рисуется, а PNG теряет вектор и требует отдельной проверки кегля. Graphviz остаётся внутри генератора как движок расстановки для компонентных схем, иерархий, состояний и блок-схем; рисует генератор сам, поэтому стиль от `dot` не зависит.

## 3. Дизайн-система

`editorial/diagram-style.ru.md`: облик, восемь ролей с закреплёнными цветами (человек, агент, программа платформы, хранилище, ключ или аппаратный модуль, внешняя система, тревога, нейтральный элемент), шрифты, границы доверия, стрелки, номера шагов и протоколы, таблица всех видов диаграмм с раскладкой, печатный бюджет и формат исходника. Тема `scripts/diagram-kit/theme.toml` держит все цвета, кегли и отступы и печатный бюджет книги.

Печатный бюджет добавлен по находке пилота. Книга вписывает рисунок в 167 × 98 мм (с `tall` в 167 × 168 мм). Первые вертикальные рендеры в таком поле давали описание кеглем 3–6 pt. Генератор теперь печатает кегль после вписывания (`--report`), тема стала плотнее, порог 7 pt.

Все четыре помещаются только в высокое поле. При замене рисунка в главе ссылка получает класс `{.tall}`; в записке `trust-chain` сейчас стоит с `{height=72mm}`, для v2 высоту нужно поднять, иначе кегль упадёт ниже 4 pt.

Содержание пилотов взято из прежних исходников и глав, новых фактов нет. Отличия: `federated-command-v2` разложен по трём зонам (сторона отправителя, серверы доставки, сторона получателя) по главе «Команда через два сервера», описания элементов взяты из её текста; в `grant-issue-and-check-v2` тире в подписи шага 3 заменено двоеточием по правилам прозы; в `bridge-components-v2` у шагов главного пути есть номера, связи с хранилищем без номеров; в `trust-chain-v2` цепочка Matrix развёрнута в три узла, ключ агента вынесен отдельным узлом под корнем Keymaker, описания взяты из таблицы главы «Кто держит ключи».

## 5. Что поменять в инструментах (не сделано в этой задаче)

1. `book/check-figures.sh`: ссылки глав принимать как `../diagrams/<имя>.png` и `.svg`; исходник искать как `src/<имя>.puml` или `src/<имя>.toml`; цикл по исходникам расширить на `*.toml`; проверку рендера без исходника расширить на `*.svg`. Для `.toml` добавить свежесть: рендер во временный файл и `cmp` с `diagrams/<имя>.svg` (генератор детерминирован). Добавить печатный бюджет: `render.py --report`, отказ при `fits: no` и при `fits: tall`, если ссылка в главе без `{.tall}`.
2. `book/src/MANIFEST.md`: колонка «Исходник» допускает `.toml`; рядом с командой PlantUML команда генератора: `python3 scripts/diagram-kit/render.py book/src/<имя>.toml book/diagrams/<имя>.svg --report`. Строки для `-v2` добавляются при замене рисунка, вместе со сменой ссылки в главе.
3. `book/build.sh`: сборка SVG не меняется, WeasyPrint вставляет его как есть. Добавить вызов `book/check-figures.sh` перед pandoc, чтобы устаревший или слишком мелкий рисунок не попадал в PDF. Graphviz нужен только для рендера, не для сборки; PT Sans и PT Mono уже обязательны.
4. `editorial/style.ru.md`, раздел «Книга: техника»: пункт о диаграммах сменить на `book/src/<имя>.toml` и SVG со ссылкой на `diagram-style.ru.md`; правило касается всех пишущих агентов, поэтому меняется отдельным решением.
5. Скилл `architecture-diagrams` (исходный репозиторий `skill-architecture-diagrams`; в `~/.agents` лежит установленная копия): перенести `render.py`, `theme.toml`, `metrics.json`, `make-metrics.py`, `test_render.py` в `scripts/` скилла; добавить `references/house-style.md` (английский пересказ ролей, границ, стрелок, видов и печатного бюджета); в SKILL.md сделать генератор путём по умолчанию для новых диаграмм, а проектную тему подключать флагом `--theme`; PlantUML и Structurizr оставить для C4 и чужих проектов. После переноса `scripts/diagram-kit/` в этом репозитории заменяется вызовом скилла с закреплённой ревизией.
6. Скилл `platform-book` (`relux-works/skill-platform-book`), которым собирается записка: команда `figures` рендерит PlantUML по `figures.json`. Нужен выбор рендерера по расширению (`.toml` → генератор) с теми же полями `source_sha256` и `render_sha256`. До этого `-v2` записки в `figures.json` не вносятся, главы на них не ссылаются.
7. README: строка инструмента в таблице добавлена в этой задаче.

Порядок миграции после принятия стиля: сначала правки 1–3 и 5, затем перерисовка по видам (короткие потоки и границы доверия в `stack`, затем последовательности, затем графы), каждая волна с проверкой `--report` и ревью глазами. Схемы устройств генератор не рисует; если они появятся, их рисуют вручную по правилам гайда.
