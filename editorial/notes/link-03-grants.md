# Link 0.3-rc1: source and illustration map

This editorial note records the sources for the human-to-agent grant revision. It is not a new protocol specification or an independent acceptance verdict. Russian book chapters remain the source text. Talk and Forum changes are limited to terminology, locator boundaries, and the associated status entries.

## Conflicts and status evidence

- Public LIP-0004 section 4 still describes bare output as the first implementation; LIP-0005 section 4 still describes framing as a follow-up. The pinned implementation writes framed output. Optional root Nostr metadata also postdates LIP-0004's original exact name shape. The book names the profiles; specification reconciliation remains open.
- The specification has no standalone LIP-0006 file at the pinned head. Exact service fields come from the public wallet laboratory profile. General publication and cross-user host qualification remain open.
- `conformance/v0.1/mainnet-2026-11-08.json` supports two historical revocation cycles. Only the second separately observed the mempool stage. The record publishes hashes, not complete grant envelopes. LIP-0002 and the single-use README describe a local journal append as the mainnet effect, not real repository creation.
- Full rental rehearsal results are reported inputs. Laboratory `experiments/m5-rehearsal/README.md` documents genuine Core with a macOS manager helper, registrar overlay and fake HTTPS model upstream. About 80 seconds for revocation and 224 seconds for expiry are observations, not delay bounds or current-head host qualification.
- Wallet implementation and independent review are reported inputs. Same-user socket tests do not prove that another OS user cannot read the service's custody files. The status table retains this qualification requirement.
- Courier facts come from laboratory `experiments/grantcheck/README.md` and `DESIGN.md`; Blossom from `experiments/grant-store/README.md`. A complete grant presentation is admitted at the delivery boundary. Fetching, storing, or delivering it does not authorize a payment. Blossom access control is not encryption against its operator.
- The older shared standing seal and universal one-year duration statements were removed from the v3 explanation: this profile requires one seal per grant and supplies its own validity interval. No new general lifetime limit is invented.

## Verification scope

The producer runs `sh scripts/check.sh`, the existing `python3 scripts/check-self-test.py`, `git diff --check`, and source-only Markdown/field-order checks. The checker self-tests include known violations and valid controls. The task-scoped source check compares diagram field order to the pinned Go JSON tags, parses illustrative JSON, verifies balanced fences and the locator layout, and checks its own field-order/fence rejection with isolated mutations.

Existing product coverage was inspected as a source, not rerun or claimed as producer execution: `TestIssuanceLocatorBinding`, `TestGrantPoolPlans`, `TestN1Values`/`TestN1Refusals`, `TestGrantSignatureDomain`, `TestJournalExtractionContract`, `TestActionGolden`/`TestActionWire`/`TestActionProof`, and `TestCoreActionRefusals`. These provide positive controls beside malformed locators, discovery-only changes, seal funding, signature confusion, replay and refused-action counterexamples.

No product code changed, so a new product test suite would not exercise this documentation delta. Source checks do not prove cryptographic validity, live network behaviour, general legal enforceability or rendered layout. Independent prose/fact review and PDF/figure rendering belong to the subsequent review and release stages. Exact commands, output, exit codes and source-check code accompany the delivery packet.
