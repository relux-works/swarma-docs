# После демо: продукт и решения

Хакатон проверяет, понимает ли человек ограниченное разрешение и получает ли полезный ответ. Для продукта нужны устойчивость и воспроизводимые гарантии на реальных устройствах, а не больше экранов. Следующий порядок работ предлагается как обратная связь в roadmap платформы. ⟦предложено⟧

| Следующий результат | Что возвращается в платформу |
| --- | --- |
| Совместимый Signer core и key provider | Общие векторы контракта подписанных сообщений, проверка отмены и точных байтов; утверждённый язык и ABI |
| XMPP-провайдер a2a | Явный контракт адресов, аудитории, повторов и квитанций; проверка двух доменов и смены OMEMO-устройств |
| Автоматический provisioning | Создание учётки ОС, ключа, аккаунта, профиля и сессии с восстановлением после частичного сбоя |
| Потеря устройства без потери контроля | Резерв корня, отзыв входа и E2EE, freshness и anti-rollback реестра; проверка offline и разделения сети |
| Продуктовый мобильный lifecycle | APNs без текста, background/reconnect, миграция crypto-store и история без потери границ доверия |
| Безопасные межвладельческие инструменты | Узкие API данных вместо доступа модели ко всему; тесты области, аудит без лишнего содержания |
| Работа на разных станциях | Контракты сессий и launch-политик, явное владение и остановка; брокер логинов остаётся отдельным владельцем секретов |

Готовность подтверждается сквозными испытаниями: допустимый семейный запрос проходит; расширение прав, повтор, отмена и отзыв не создают эффекта. Для каждого нового допускающего правила нужен контроль, который удаляет именно его и воспроизводит запрещённый исход. Две реализации, одинаково принимающие ошибочный запрос, не заменяют нормативное ожидание.
