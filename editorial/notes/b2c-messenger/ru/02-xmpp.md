# Какой XMPP нужен продукту

Недостаточно выбрать сервер с надписью «поддерживает XMPP». Перед реализацией команда фиксирует версии сервера, библиотек и расширений, затем проверяет одну совместимую комбинацию. Ниже — предлагаемый профиль, а не протокол собственной разработки. Статус XEP не доказывает поддержку в выбранном клиенте. ⟦предложено⟧

| Возможность | Конкретное расширение | Место в MVP и обязательная проверка |
| --- | --- | --- |
| Шифрование | [XEP-0384 OMEMO](https://xmpp.org/extensions/xep-0384.html), 0.9.1, Experimental | Основной путь. Зафиксировать общий профиль; проверить новое устройство, offline-доставку и смену ключа без молчаливого доверия |
| Группы | [XEP-0045 MUC](https://xmpp.org/extensions/xep-0045.html) | Выбрать для маленькой закрытой группы. Проверить режим членства, удаление участника и список получателей OMEMO |
| Альтернатива группам | [XEP-0369 MIX](https://xmpp.org/extensions/xep-0369.html) | После MVP; не считать взаимозаменяемым с MUC. Проверить сервер, клиент и сочетание с OMEMO до включения |
| Ключи устройств | [XEP-0060 PubSub](https://xmpp.org/extensions/xep-0060.html), [XEP-0163 PEP](https://xmpp.org/extensions/xep-0163.html) | Получение OMEMO bundles и списков устройств. Проверить федеративное чтение, недоступность и смену списка |
| История | [XEP-0313 MAM](https://xmpp.org/extensions/xep-0313.html), 1.1.3 | Архив зашифрованных сообщений. Проверить возврат после offline; наличие архива не даёт новому устройству старые ключи |
| Несколько клиентов | [XEP-0280 Carbons](https://xmpp.org/extensions/xep-0280.html), 1.0.1 | Доставка копий на свои ресурсы; проверить дубли и E2EE для каждого допущенного устройства |
| Уведомления | [XEP-0357 Push](https://xmpp.org/extensions/xep-0357.html), 0.4.1, Deferred | Проверить сервер, push-сервис и iOS в фоне. При неготовности — явно foreground-only демо; никаких секретов в preview |
| Вложения | [XEP-0363 HTTP Upload](https://xmpp.org/extensions/xep-0363.html), 1.2.0 | Вне основного демо. Проверить клиентское шифрование файла и передачу ключа внутри E2EE: upload сам файл не шифрует |
| Серверный стык | [XEP-0114 Component Protocol](https://xmpp.org/extensions/xep-0114.html), 1.6 | Кандидат для bridge-компонента. Проверить аутентификацию и маршрутизацию; права компонента не заменяют подписи агентов |
| Вход на ключе | [XEP-0178 SASL EXTERNAL](https://xmpp.org/extensions/xep-0178.html), 1.2 | Кандидат с клиентским сертификатом и PKIX. Проверить связь JID с ключом, provisioning, отзыв и поддержку в iOS/сервере |

Для первой сборки можно оставить мост обычным XMPP-клиентом на станции, а component-стык отложить. Если используется XEP-0114, серверный компонент только маршрутизирует; OMEMO завершается в доверенном локальном адаптере агента. Перенос расшифровки на общий сервер меняет модель и должен называться другим вариантом продукта. ⟦предложено⟧

## Чего не даёт парольless-вход

Passkey, подпись `swarm-envelope/2`, TLS-сертификат и OMEMO-ключ — разные механизмы. SASL EXTERNAL не означает автоматической поддержки WebAuthn или ключа Ed25519 ключника. [XEP-0388](https://xmpp.org/extensions/xep-0388.html) описывает расширяемый SASL-профиль, а [XEP-0440](https://xmpp.org/extensions/xep-0440.html) — объявление channel binding; ни один не является готовым входом «любым ключом Swarma».

Пока общий путь не проверен, аккаунты для демонстрации создаются вручную, сертификаты настраиваются отдельно. На экране явно написано: «Вход подготовлен для демо». Нельзя переименовать пароль или JWT в key-based аккаунт и считать требование выполненным. Выбор окончательного входа остаётся открытым. ⟦предложено⟧
