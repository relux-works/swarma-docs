# Какой XMPP нужен продукту

«Сервер поддерживает XMPP» — этого мало. XMPP — это ядро плюс десятки расширений (XEP), и каждый клиент поддерживает свой набор. Поэтому перед разработкой команда фиксирует конкретные версии сервера, библиотек и расширений и проверяет, что они работают вместе. Ниже — предлагаемый набор, а не наш собственный протокол. ⟦предложено⟧

| Что нужно | Расширение | Зачем в MVP и что проверить |
| --- | --- | --- |
| Шифрование | [XEP-0384 OMEMO](https://xmpp.org/extensions/xep-0384.html) 0.9.1 (статус Experimental) | Основа. Проверить новое устройство, доставку после офлайна и смену ключа без молчаливого доверия |
| Группы | [XEP-0045 MUC](https://xmpp.org/extensions/xep-0045.html) | Маленькая закрытая группа. Проверить членство, удаление участника и список получателей шифрования |
| Каналы | [XEP-0369 MIX](https://xmpp.org/extensions/xep-0369.html) | После MVP. Это не замена MUC один в один; совместимость с OMEMO проверить отдельно |
| Ключи устройств | [XEP-0060 PubSub](https://xmpp.org/extensions/xep-0060.html), [XEP-0163 PEP](https://xmpp.org/extensions/xep-0163.html) | Публикация ключей OMEMO и списков устройств. Проверить чтение через федерацию и смену списка |
| История | [XEP-0313 MAM](https://xmpp.org/extensions/xep-0313.html) 1.1.3 | Архив зашифрованных сообщений. Новое устройство старые ключи из архива не получает |
| Несколько устройств | [XEP-0280 Carbons](https://xmpp.org/extensions/xep-0280.html) 1.0.1 | Копии на свои устройства. Проверить дубли и шифрование для каждого устройства |
| Уведомления | [XEP-0357 Push](https://xmpp.org/extensions/xep-0357.html) 0.4.1 (статус Deferred) | Проверить сервер, push-сервис и iOS в фоне. Не готово — честно показываем демо только с открытым приложением; никакого текста в уведомлении |
| Файлы | [XEP-0363 HTTP Upload](https://xmpp.org/extensions/xep-0363.html) 1.2.0 | Вне основного демо. Upload сам файл не шифрует: шифруем на клиенте, ключ передаём внутри OMEMO |
| Стык с сервером | [XEP-0114 Component Protocol](https://xmpp.org/extensions/xep-0114.html) 1.6 | Кандидат для моста агентов. Права компонента не заменяют подписей агентов |
| Вход по ключу | [XEP-0178 SASL EXTERNAL](https://xmpp.org/extensions/xep-0178.html) 1.2 | Вход по клиентскому сертификату. Проверить связь адреса с ключом, выпуск, отзыв и поддержку на iOS и сервере |

Для первой сборки мост агента может быть обычным XMPP-клиентом на станции, без серверного компонента. Если мы всё же используем компонент, он только пересылает сообщения, а расшифровка остаётся у агента на станции. Расшифровка на общем сервере — это уже другой продукт, и называть его надо по-другому. ⟦предложено⟧

## Чего не даёт вход без пароля

Passkey, подпись нашего конверта `swarm-envelope/2`, TLS-сертификат и ключ OMEMO — четыре разных механизма. Вход по SASL EXTERNAL не означает, что сервер понимает WebAuthn или ключи Keymaker. Расширения [XEP-0388](https://xmpp.org/extensions/xep-0388.html) и [XEP-0440](https://xmpp.org/extensions/xep-0440.html) задают рамки, но не дают готового входа «любым ключом Swarma».

Пока этот путь не проверен, аккаунты для демо заводим вручную, а сертификаты настраиваем отдельно. На экране так и написано: «Вход подготовлен для демо». Нельзя назвать пароль или JWT «входом по ключу» и считать задачу решённой. Какой вход будет в продукте — открытый вопрос. ⟦предложено⟧
