# Что собираем на хакатоне

Цель — показать ограниченный полезный путь и его отказы. Не требуется закончить весь рантайм, но каждый mock виден зрителю. Следующая граница предлагается для первой команды. Реальная криптография берётся из проверенной библиотеки; собственный учебный OMEMO не строится. ⟦предложено⟧

| Реально строим и проверяем | Имитируем, готовим вручную или откладываем |
| --- | --- |
| Минимальный iOS-клиент: список чатов, разговор, карточка разрешения, явные состояния ошибки | Полноценный desktop-клиент: пока контрольная панель/существующий клиент без заявления совместимости Signer |
| E2EE-переписка двух людей и разговор с агентом на одном выбранном профиле OMEMO | Собственный серверный бренд и выбор провайдеров; все аккаунты подготовлены вручную |
| Один локальный XMPP-адаптер к одному harness через хост сессий | Автоматическое развёртывание станции, всех учёток и произвольных агентов |
| Проверка ограниченного разрешения перед чтением только свободных интервалов тестового календаря | Настоящие личные календари, платежи, удаление реальных данных |
| Положительный запрос, отказ на лишние поля/операции, отзыв и повтор запроса | Если общий verifier не готов — явно симулированный результат без доступа к реальным инструментам |
| Корневая аттестация подготовленных тестовых ключей и проверка цепочки, когда доступен совместимый модуль | Корневая церемония — ручная; автоматическое восстановление после полной потери корня отсутствует |
| Face ID и аппаратная подпись — только если работают точные байты и verifier | Иначе карточка помечена «симуляция подтверждения»; критический реальный эффект закрыт |
| Проверяемый журнал вердиктов без plaintext чувствительных данных | Push, вложения, MIX, широкий discovery и несколько моделей — после основного пути |

## Демо на шесть с половиной минут

Это предложенный тайминг сценария, не измеренная скорость продукта.

1. **0:00–0:45.** Два человека обмениваются сообщениями; показать E2EE и границу метаданных.
2. **0:45–1:45.** Привязать телефон к подготовленной станции: QR и SAS либо честная ручная сверка.
3. **1:45–2:30.** Попросить календарного помощника; показать отдельную личность и подготовленный профиль, назвать ручной provisioning.
4. **2:30–4:00.** Выдать узкий семейный грант. Спросить про пятницу и получить только свободные интервалы.
5. **4:00–5:00.** Попросить название встречи/удаление: отказ. Показать, что приглашение в чат не дало доступа.
6. **5:00–6:00.** Отозвать грант и повторить ранее успешный запрос: отказ; затем показать допустимый запрос собственного владельца.
7. **6:00–6:30.** Показать отмеченные mock-компоненты и следующий проверяемый этап: второй домен или mobile push.

## Риски и fallback

| Риск | Проверка до демонстрации | Допустимое упрощение |
| --- | --- | --- |
| OMEMO-профили несовместимы | Два клиента, offline, новое устройство, подменённый fingerprint | Одна согласованная пара клиентов; plaintext не выдаётся за E2EE |
| Ключевой SASL не готов | Реальная аутентификация и отзыв на выбранном сервере | Ручной вход с явной маркировкой; не обещать key-based onboarding |
| Нет совместимого trust-core | Разрешённый запрос и отказ на изменённую цель/отзыв | Только симуляция с тестовым календарём, без реальных эффектов |
| iOS не получает push | Заблокированный экран, возврат из фона | Foreground-only демонстрация с объяснением ограничения |
| Федерация недоступна | Два домена, совпадение ключей и отказ на подмену | Один сервер; не называть это проверенной федерацией |
| Native session bridge теряет ход | Обрыв/повтор доставки, явная квитанция исполнения | Один заранее запущенный агент; не выдавать доставку за исполнение |
