# Что собираем на хакатоне

Цель — показать один полезный путь от начала до конца и то, как система отказывает там, где должна. Доделывать всю платформу не нужно, но каждая имитация видна зрителю. Шифрование берём из проверенной библиотеки, свой OMEMO не пишем. ⟦предложено⟧

| Строим по-настоящему | Имитируем, готовим вручную или откладываем |
| --- | --- |
| Простой iOS-клиент: список чатов, разговор, карточка разрешения, понятные ошибки | Полноценный клиент для компьютера; пока панель на станции |
| Шифрованная переписка двух людей и разговор с агентом на одной выбранной связке OMEMO | Свой бренд сервера и выбор провайдеров; аккаунты заведены вручную |
| Один адаптер XMPP к одному агенту через хост сессий | Автоматическое развёртывание станции и создание любых агентов |
| Проверка узкого разрешения перед чтением только свободного времени из тестового календаря | Настоящие личные календари, платежи, удаление реальных данных |
| Разрешённый запрос, отказ на лишнее, отзыв и повтор запроса после отзыва | Если общей проверки ещё нет — явная симуляция без доступа к настоящим инструментам |
| Аттестация тестовых ключей корнем и проверка цепочки, если модуль готов | Церемония корня вручную; восстановления после полной потери корня нет |
| Face ID для критичных действий — **только как помеченная симуляция**: в v0 A3 не квалифицирован | Настоящий критичный эффект закрыт |
| Журнал решений проверки без чувствительного текста | Push, файлы, MIX, поиск людей, несколько моделей — после основного пути |

## Демо на шесть с половиной минут

Это план сценария, а не замер скорости продукта.

1. **0:00–0:45.** Два человека переписываются. Показываем шифрование и что сервер видит только метаданные.
2. **0:45–1:45.** Привязываем телефон к станции: QR и эмодзи или честная ручная сверка отпечатка.
3. **1:45–2:30.** Просим помощника-календарь. Показываем отдельную личность и заранее подготовленный профиль; прямо говорим, что создан вручную.
4. **2:30–4:00.** Выдаём узкое семейное разрешение. Спрашиваем про пятницу и получаем только свободные интервалы.
5. **4:00–5:00.** Просим название встречи или удалить её — отказ. Показываем, что приглашение в чат доступа не дало.
6. **5:00–6:00.** Отзываем разрешение и повторяем тот же запрос — отказ. Затем владелец задаёт свой разрешённый вопрос — проходит.
7. **6:00–6:30.** Показываем, что было имитацией (включая Face ID), и следующий шаг: второй сервер или push.

## Риски и запасные варианты

| Риск | Что проверить заранее | Допустимое упрощение |
| --- | --- | --- |
| Клиенты OMEMO несовместимы | Два клиента, офлайн, новое устройство, подменённый отпечаток | Одна проверенная пара клиентов; открытый текст не выдаём за шифрование |
| Вход по ключу не готов | Настоящий вход и отзыв на выбранном сервере | Ручной вход с явной пометкой |
| Нет общего ядра проверки | Разрешённый запрос и отказы при подмене цели и после отзыва | Только симуляция на тестовом календаре |
| iOS не получает push | Заблокированный экран, возврат из фона | Демо с открытым приложением и объяснением |
| Федерация не работает | Два домена, сверка ключей, отказ при подмене | Один сервер; не называем это проверенной федерацией |
| Мост к сессии теряет сообщения | Обрыв и повтор доставки, отдельная квитанция исполнения | Один заранее запущенный агент; доставку не выдаём за исполнение |
