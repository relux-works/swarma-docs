# Люди и их агенты

Закрытый продуктовый документ для оператора и команды хакатона. Русский текст — источник правды. [PDF](b2c-messenger.ru.pdf) собран из `ru/`, диаграммы — из `src/`. Это проект потребительской сборки платформы, а не отчёт о готовом мессенджере. Новые связи, UI и сценарии помечены как предложения; ручная подготовка и симуляции названы прямо.

## План и границы

| Главы | Вопрос |

Все адреса `example.test` вымышлены. Юридические, лицензионные, личные и связанные с работодателями части исходного разговора исключены. Этот каталог и PDF не предназначены для публичной доски или публичного репозитория.

Публичные основания указаны рядом с утверждениями в главах 1–2: Matrix Specification **v1.19**, официальные каталоги клиентов и страницы XEP. На дату среза отдельно проверены XEP-0384 **0.9.1 Experimental**, XEP-0357 **0.4.1 Deferred**, XEP-0313 **1.1.3**, XEP-0280 **1.0.1**, XEP-0363 **1.2.0**, XEP-0114 **1.6**, XEP-0178 **1.2**. Ссылки XEP ведут на изменяемые официальные страницы: перед выбором реализации версии проверяются повторно. Статус стандарта не доказывает совместимость сервера и клиентов.

SASL EXTERNAL описывает сертификаты и PKIX; его нельзя объявлять готовым входом через любой Ed25519-ключ или passkey. OMEMO и прикладные подписи проверяются раздельно. Серверы могут видеть метаданные; конечный агент и его модель могут видеть plaintext. Отсутствие общего verifier или проверяемого присутствия закрывает реальный критический эффект, даже если экран подтверждения уже нарисован.

Решения, которых пока нет, собраны в [UNRESOLVED_QUESTIONS.md](UNRESOLVED_QUESTIONS.md) и в последней главе. Демо проверяет продуктовую гипотезу на тестовом календаре; его тайминг предложен, а не измерен.

## Инструменты и воспроизведение

Использован `platform-book` на ревизии `1c75fdf4a09960e41ea153645da7c48800b7a82b`, без изменения его CSS, шрифтов или фильтра. Нужны Python **3.12.15**, Pandoc **3.11**, WeasyPrint **70.0**, pypdf **5.9.0**, нативные библиотеки Pango и девять bundled-шрифтов пакета. Python-зависимости устанавливаются в обычный изолированный venv по `requirements-lock.txt` самого пакета. Системные зависимости не устанавливаются этой инструкцией.

Команды выполняются из корня репозитория. `BOOK_SKILL` указывает на исходный checkout ровно указанной ревизии; `SCRATCH` — на собственный временный каталог внутри `.temp/`.

```sh
BOOK_SKILL=../skill-platform-book
NOTE=editorial/notes/b2c-messenger
SCRATCH=.temp/b2c-messenger-build
mkdir -p "$SCRATCH"
python3.12 -m venv "$SCRATCH/venv"
. "$SCRATCH/venv/bin/activate"
python -m pip --no-cache-dir install -r "$BOOK_SKILL/requirements-lock.txt"
# macOS: каталог уже установленных Pango-библиотек, если нужен loader override.
export PLATFORM_BOOK_LIBRARY_PATH=/opt/homebrew/lib
"$BOOK_SKILL/scripts/platform-book" ready
"$BOOK_SKILL/scripts/platform-book" figures "$NOTE"
"$BOOK_SKILL/scripts/platform-book" build "$NOTE" "$NOTE/b2c-messenger.ru.pdf"
"$BOOK_SKILL/scripts/platform-book" check-pdf "$NOTE/b2c-messenger.ru.pdf" \
  --expected-pages 23 --fonts 'PT Serif' 'PT Sans' 'PT Mono'
sh scripts/check.sh
```

| Инструмент | Назначение и команда | Выход |
| --- | --- | --- |
| `platform-book ready` | Проверить точные версии, загрузку библиотек и hashes шрифтов | Вердикт в stdout |
| `platform-book figures "$NOTE"` | Проверить восемь пар исходник/render и разрешённые ресурсы | Вердикт в stdout |
| `platform-book build "$NOTE" "$NOTE/b2c-messenger.ru.pdf"` | Markdown → Pandoc → WeasyPrint с общим книжным оформлением | Проверенный PDF в этом каталоге |
| `platform-book check-pdf …` | Проверить 23 страницы, наличие текста, семейства и встраивание шрифтов | JSON в stdout; это не визуальная проверка |
| PlantUML **1.2026.6**, Graphviz | `plantuml -tsvg -o ../diagrams "$NOTE"/src/*.puml` | Восемь SVG в `diagrams/`; затем нормализация ниже |
| Python `hashlib`, `json` | Записать SHA-256 фактических байтов каждой пары | `src/figures.json` |
| Poppler | `pdftoppm -scale-to 1200 -png "$NOTE/b2c-messenger.ru.pdf" "$SCRATCH/page"`; `pdftotext -layout …` | Временные изображения и извлечённый текст в `$SCRATCH` |
| `sh scripts/check.sh` | Проверить основную книгу и пейпер | stdout; `editorial/` этим скриптом не покрывается |

PlantUML по умолчанию выпускает `preserveAspectRatio="none"`. После рендера у корневого SVG заменяем это значение на `xMidYMid meet`, чтобы заданная высота рисунка не искажала буквы. Затем пересчитываем manifest. Это нормализация render, а не ручная правка схемы:

```sh
python - <<'PY'
from pathlib import Path
import hashlib, json
root = Path('editorial/notes/b2c-messenger')
for render in (root / 'diagrams').glob('*.svg'):
    text = render.read_text().replace('preserveAspectRatio="none"',
                                      'preserveAspectRatio="xMidYMid meet"')
    render.write_text(text)
manifest = {}
for source in sorted((root / 'src').glob('*.puml')):
    render = root / 'diagrams' / (source.stem + '.svg')
    manifest[source.stem] = {
        'source': str(source.relative_to(root)),
        'render': str(render.relative_to(root)),
        'source_sha256': hashlib.sha256(source.read_bytes()).hexdigest(),
        'render_sha256': hashlib.sha256(render.read_bytes()).hexdigest(),
    }
(root / 'src/figures.json').write_text(json.dumps(manifest, indent=2) + '\n')
PY
```

Перед передачей дополнительно проверяются гигиена новых Markdown, исходников схем и извлечённого текста PDF, все шесть сценариев и наличие отрицательных контролей рядом с разрешёнными путями. Нужен визуальный просмотр обложки, оглавления, таблиц, каждой схемы, статусов и последней страницы. Проверка числа страниц и hashes сама по себе этого не доказывает. Для сборочного инструмента используются изолированные контрольные нарушения: неверное число страниц и изменённый исходник рисунка при старом hash; отказ сборки должен сохранить существующий выход.
