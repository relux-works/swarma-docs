# Как устроить Signer и что решить

Core выделяется из `a2a-swarm`; CLI `a2a` — один из интерфейсов. Core проверяет и строит конверты, проверяет цепочки и гранты. Адаптеры: сначала Matrix, затем XMPP. Синхронизатор получает снимки реестра; детерминированные ворота выносят вердикт по ним, без сетевого запроса.

Приложения macOS/iOS встраивают core как framework. UI и состояние — Relux Swift, организация — Tuist и packages, вход — device flow. Вход и служебное состояние в Keychain не заменяют root-аттестацию. Секрет остаётся за key provider в Secure Enclave/FIDO; core получает публичные сведения и результат операции.

## Разделение ответственности

1. **Seraph:** формат конверта, аттестаций и отзывов; векторы совместимости. Как у регистратора, другие реализации проходят один набор позитивных и негативных векторов.
2. **A2A:** выделение core и интерфейс CLI; одинаковая проверка независимо от транспорта.
3. **Signer:** приложения Mac/iPhone и системный key provider с показом точного действия.
4. **Keymaker:** namespace `swarma-msg` для агентских подписей. Секреты не переезжают в core или процесс агента.

## Открытые решения

| Вопрос | Что нужно закрепить до совместимой реализации |
| --- | --- |
| Язык core | исследование рекомендует Rust/UniFFI с Matrix Rust SDK; ревью ещё не завершено, выбор открыт |
| XMPP | сроки, отображение адресов и комнат, OMEMO-проверка без cross-signing |
| Резерв корня | церемония резерва/восстановления, замена и компрометация FIDO-корня; связь с долгоживущими корнями книги |
| Реестр | доступность, допустимая свежесть и fail closed при недоступности; книга задаёт снимки не старше 60 секунд, но режим Signer ещё требует контракта |
| Присутствие и WC1 | проверяемое связывание присутствия с действием; где живёт witness WC1, кто его проверяет и как учитывается время отзыва |
| Кодировки | кодировка подписи и вывод `key_id`; алгоритмы Ed25519 и P-256 low-S уже предусмотрены планом S0 |
| Байты и повторы | состав подписываемого тела CCJ-1, ссылки на гранты, окно `ts`, хранение nonce, восстановление и внешняя идемпотентность |

Численное окно конверта, коды отказов и формат WC1 здесь не вводятся. Для выпуска нужны опубликованные контракты и общие векторы; принятая архитектура ещё не свидетельствует об их реализации.
