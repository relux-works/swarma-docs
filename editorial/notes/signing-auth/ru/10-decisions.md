# Как устроен Signer

Core выделяется из `a2a-swarm`; CLI `a2a` — один из интерфейсов. Core проверяет и строит конверты, проверяет цепочки и гранты. Адаптеры: сначала Matrix, затем XMPP. Синхронизатор получает снимки реестра; детерминированные ворота выносят вердикт по ним, без сетевого запроса.

Приложения macOS/iOS встраивают core как framework. UI и состояние — Relux Swift, организация — Tuist и packages, вход — device flow. Вход и служебное состояние в Keychain не заменяют root-аттестацию. Секрет остаётся за key provider в Secure Enclave/FIDO; core получает публичные сведения и результат операции.

## Разделение ответственности

1. **Seraph:** формат конверта, аттестаций и отзывов; векторы совместимости. Как у регистратора, другие реализации проходят один набор позитивных и негативных векторов.
2. **A2A:** выделение core и интерфейс CLI; одинаковая проверка независимо от транспорта.
3. **Signer:** приложения Mac/iPhone и системный key provider с показом точного действия.
4. **Keymaker:** namespace `swarma-msg` для агентских подписей. Секреты не переезжают в core или процесс агента.

## Контракты проверки

Контракт Seraph и общие векторы фиксируют кодировки и подписываемые байты, проверку времени и повторов. Контракт реестра задаёт доступность, свежесть и отказ при недоступности. Для присутствия требуется проверяемая связь с действием; свидетельство WC1 проверяется с учётом времени отзыва. Проверка восстановления охватывает потерю корня и журнала повторов, а внешний эффект требует идемпотентности.

Для выпуска нужны опубликованные контракты и общие векторы. Численное окно конверта, коды отказов и формат WC1 задаются соответствующими контрактами.
