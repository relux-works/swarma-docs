# Как устроить Signer и что решить

Один core выделяется из `a2a-swarm`; CLI `a2a` остаётся интерфейсом. Core строит и проверяет конверты, цепочки и гранты, синхронизирует реестр и подключает адаптеры: сначала Matrix, затем XMPP. Отдельный синхронизатор получает снимки; детерминированные ворота работают по проверенным снимкам, не ходят в сеть при вердикте.

Приложения macOS и iOS встраивают core как framework. UI и состояние — Relux Swift, организация — Tuist и packages, вход — device flow. Авторизация в приложении и хранение служебного состояния в Keychain не заменяют root-аттестацию. Подписывающий ключ остаётся за key provider в Secure Enclave либо на FIDO-токене; core видит публичные сведения и результат операции.

## Разделение ответственности

1. **Seraph:** формат конверта, аттестаций и отзывов; векторы совместимости. Как у регистратора, другие реализации проходят один набор позитивных и негативных векторов.
2. **A2A:** выделение core и интерфейс CLI; одинаковая проверка независимо от транспорта.
3. **Signer:** приложения Mac/iPhone и системный key provider с показом точного действия.
4. **Keymaker:** namespace `swarma-msg` для агентских подписей. Секреты не переезжают в core или процесс агента.

## Открытые решения

| Вопрос | Что нужно закрепить до совместимой реализации |
| --- | --- |
| Язык core | Go/gomobile, Rust/UniFFI или Swift; исследование продолжается |
| XMPP | сроки, отображение адресов и комнат, OMEMO-проверка без cross-signing |
| Резерв корня | церемония резерва/восстановления, замена и компрометация FIDO-корня; связь с долгоживущими корнями книги |
| Реестр | доступность, допустимая свежесть и fail closed при недоступности; книга задаёт снимки не старше 60 секунд, но режим Signer ещё требует контракта |
| Присутствие и WC1 | проверяемое связывание присутствия с действием; где живёт witness WC1, кто его проверяет и как учитывается время отзыва |
| Байты и повторы | точный preimage CCJ-1, алгоритмы и кодировки, ссылки на гранты, окно `ts`, хранение nonce, восстановление и внешняя идемпотентность |

Ни численного окна для конверта, ни нового кода отказа, ни формата WC1 эта записка не вводит. Перед выпуском нужны опубликованные контракты и общие векторы; принятая архитектура сама по себе не свидетельство их реализации.
