# Листы решений для финализации дизайна

Черновик для владельца, 17 октября 2026. В книге 631 пометка «предложено» или «открыто». Решаются они так:

- **«Предложено» (около 510)** — проработанный дизайн модулей, прошедший циклы ревью. Рекомендация: принять целиком как решённый дизайн, кроме мест, которые ниже решаются иначе.
- **«Открыто» (121)**, из них около половины — «точный формат ещё не опубликован». Дизайн там решён, формат задаёт спецификация модуля; пометку снимаем, в тексте остаётся «точный формат — в спецификации модуля».
- **Настоящие развилки** — ниже, по блокам, с рекомендацией. Ответ «принимаю рекомендации, кроме …» закрывает их все.

## Рантайм

1. **Исполнитель действий с репозиторием.** Публикацию кандидата, передачу артефактов раннерам, обновление базы и приземление выполняет отдельная служба под собственной системной учёткой, не агент. Свои учётные данные она получает через брокер; полномочия проверяет на границе действия по подписанному доской запросу, привязанному к точному кандидату; продвижение головы — сравнение-и-замена. *Рекомендация: да.* *Сверка с решением 76 (27 октября 2026): исполнитель обобщается до службы действий с адаптерами сервисов и служит доверенным исполнителем эффектов протокола; любая запись во внешний сервис идёт только через неё; приёмка доской точного кандидата и сравнение-и-замена сохраняются.*
2. **Жизненный цикл SSH-входа рабочего места.** Порядок: заморозить поколение, затем закрыть вход (принципалы закрытого поколения больше не сопоставляются), затем остановить (`cgroup.kill`), затем экспорт, затем замена. Новый вход в закрытое поколение невозможен. *Рекомендация: да* (продолжение решений 1 и 2 по ревью).
3. **Сетевая заморозка поколения.** Сужение правила ядра, затем сброс сессий прокси этого поколения, затем снятие слушателя; запись о заморозке переживает перезапуск, повтор отсекается номером поколения. *Рекомендация: да.*
4. **План запуска на дескрипторе 3.** Linux — `memfd` с печатями; macOS — неименованный файл `0400`, открытый только на чтение. *Рекомендация: да.*
5. **Сохранение дома оператором.** В первой версии не предлагается: дом удаляется при выводе учётки, экспорт метаданных ограничен служебными записями. *Рекомендация: да.*
6. **Смена и компрометация мастер-секрета ключника.** Плановая смена: новый корень, повторная регистрация всех агентов под ним; непрерывность личностей держит долгоживущий ключ владельца, который удостоверяет оба корня. Компрометация: отзыв старого корня в реестре; все ключи агентов недействительны; повторная выдача. *Рекомендация: да.*
7. **Ключ оператора на телефоне.** Регистрация при установке: сопряжение по QR с подтверждением на терминале и на телефоне. Обязательно второе устройство (резервный ключ FIDO2 или второй телефон). Замена — подписью второго устройства; потеря — отзыв вторым устройством. Корень брокера v0 переносится в реестр, подписанный ключом оператора. *Рекомендация: да.*
8. **Реестр ключей и грантов.** Одна служба реестра владельца — единственный авторитетный писатель, журнал на git для аудита, службам раздаются подписанные снимки со свежестью не старше 60 секунд (решение 6 по ревью). *Рекомендация: да.*
9. **Собственные цели агента.** В первой версии их нет: цель задаёт только доска, вызывающий или оператор. Детектор отсутствия прогресса сначала работает в теневом режиме. *Рекомендация: да.*
10. **Кто поднимает постоянные команды после перезагрузки.** Swarm Keeper под своей системной учёткой по команде `keeper up` при загрузке, через диспетчер; остановленное человеком остаётся остановленным. *Рекомендация: да.*
11. **Общий стоп.** Одна команда оператора, подписанная телефоном: диспетчер замораживает все поколения, закрывает вход, отзывает аренды; возобновление — только подписью оператора. Кипер может получить доверенность на стоп с названным поводом. *Рекомендация: да.* *Сверка с решением 76: общий стоп закрывает и использования в шлюзе учётных данных и службе действий (очереди, потоки, действия) с записью закрытия.*
12. **Повторный вход у провайдера после разлогинивания.** Ведёт брокер: хост паркует сессию при отказе входа, брокер шлёт владельцу аккаунта на телефон ссылку входа, после входа выдаёт новую аренду, хост возобновляет сессию. *Рекомендация: да.* *Сверка с решением 76: повторный вход не снимает блокировку аккаунта по растяжке утечки, её снимает только владелец; маршрут уведомления задаёт спецификация брокера (оповещения открыты), парковку и возобновление ведёт хост сессий.*

## Swarma Keeper

13. **Надёжность пробуждения.** Пока пробуждение не доказано, каждый шаг эскалации идёт двумя уведомлениями (адресный вопрос и видимое человеку `owner-needed`), а эскалация не считает пробуждение выполненным. *Рекомендация: да.*
14. **Журнал обязательств.** Хранится в каталоге состояния системной учётки кипера, входит в резервную копию владельца (подписанный, без секретов); записи подписывает кипер своим ключом через ключника. *Рекомендация: да.*
15. **Время.** `skew_bound` 2 минуты; расхождение монотонных и системных часов больше границы — происшествие; без проверенного времени сроки считаются только по монотонным часам, без продлений (вместе с удержанием 10 минут по ревью). *Рекомендация: да.*
16. **Эскалация.** Новый срок вправе назначить получатель шага или выше; не больше двух продлений на эпизод, каждое не длиннее исходного шага; интервал сверки 5 минут. Плановая смена исполнения внутри участника — передача с квитанциями. Запасной владелец общего ресурса — кипер продукта, для общеплатформенных — мета-кипер. Транспортные таймеры только советуют; решает журнал кипера. *Рекомендация: да.*

## Swarm Curator и учётные данные

17. **Готовность перед запуском.** Обязательна для каждого адаптера; неквалифицированная проверка даёт «неизвестно», а «неизвестно» не запускает. *Рекомендация: да.* *Сверка с решением 76: в режиме без секретов у агента готовность входа означает доставку заглушки, а готовность пути через шлюз проверяется отдельно.*
18. **MCP.** Единое правило: любая экспозиция MCP требует явного согласия до первой записи, в том числе удалённый сервер без переменных. Единый контракт писателя конфигурации (управляемый и нативный пути) ведёт Swarm Curator. *Рекомендация: да.* *Сверка с решением 76: MCP-сервер, которому нужен токен сервиса, получает адрес шлюза учётных данных по машинной политике, а токена не получает; согласие сохраняется.*
19. **Неквалифицированные хранилища и клиенты** (OAuth при подменённом доме, принудительные хранилища, локальные Windows-серверы через `.cmd`) — отказ до квалификации. *Рекомендация: да.*

## Удалённое рабочее место

20. **Вариант A после квалификации B и C.** Для новых регистраций A закрывается: случай без прав администратора закрывает C с более сильной границей; существующих доноров A переводят на C. *Рекомендация: да.*
21. **Веб-содержимое без подтверждённого происхождения** остаётся помеченным, пока доверенная сторона не приложит получение с дайджестом. *Рекомендация: да.*

## Доска, модели, память

22. **Режим экономии моделей** включается только явным решением оператора, пока данные пилота не зададут порог потери качества. Обучаемый маршрутизатор — не в первой версии. *Рекомендация: да.*
23. **Экспорт свойств процесса в формальные инструменты** — не в первой версии. *Рекомендация: да.*
24. **Память** — по решениям владельца по памяти; классы источников и сроки предъявимости задаёт пакет спецификации памяти. *Рекомендация: да.*

## Swarma Protocol

25. **Кворум L2** — $q = \lceil (n+f+1)/2 \rceil$ (решение по ревью).
26. **Принимающий писатель** назначается по владению процессом: его держит кор-нода, у которой аренда корневого оркестратора, и он ротируется вместе с арендой. *Рекомендация: да.*

## Swarma Chain: идентичность и репутация

27. **Вывод учётки и отзыв личности** — разные действия; в цепочку попадают только удостоверения и отзывы.
28. **Приватность.** Открытые аттестации — по умолчанию для публичных проектов; приватные проекты публикуют хэш-обязательство с выборочным раскрытием.
29. **Право выдачи.** Аттестации вправе выдавать любой рантайм с личностью в цепочке; начальный вес выдающего определяется классом доказательства идентичности и растёт с его собственной историей.
30. **Репутация.** Отдельные оси: ревьювер, продьюсер, верификатор. Вес аттестации — по репутации выдавшего, с затуханием во времени. Формула и константы публикуются вместе с индексатором до запуска сети; её детерминированно пересчитывает любой.
31. **«Не установлено»** не влияет на репутацию ни в плюс, ни в минус.
32. **Споры.** Агент публикует подписанное возражение, связанное с аттестацией; индексаторы показывают оба; вес оспоренного «отклонено» снижен, пока выдавший не подтвердит его повторно. Арбитража в цепочке в первой версии нет.
33. **Формат и цена аттестации.** Минимальный состав из главы — канонический; цена — тариф текстовой записи; от спама защищает вес выдающего (свидетельства без веса почти ничего не дают).
34. **Деньги и репутация** в первой версии не связаны: оплату работы задаёт политика проекта, цепочка даёт только валюту расчётов.

*Рекомендация по блоку: да.*

## Swarma Chain: устройство и экономика

35. **Майнинг** — две дорожки: объединённая с Monero и собственная RandomX (предпочтение исходного дизайна).
36. **Фонд разработки** — 0 при честном запуске.
37. **Сложность, размер блока, хвост эмиссии** — механизм выбран (ASERT, блок 60 секунд); числа фиксируются по результатам моделирования до запуска сети.
38. **Протокол индексатора** — GraphQL с подписками.
39. **Имена** — базовая цена по длине, следующая за спросом; плата делится пополам: сжигание и майнерам, распределённо на сутки блоков.
40. **iOS** — тонкий режим без архивирования.

*Рекомендация по блоку: да.*

## Координация роя (29 октября 2026)

41. **Старшинство книги и спецификаций.** Владелец сказал 29 октября: «Книга — главный источник правды», спецификации живут в своих репозиториях и описываются в книге. Действующее правило `style.ru.md` говорит обратное: при расхождении права спецификация. *Рекомендация:* книга задаёт дизайн и понятия и старше по смыслу; спецификация модуля задаёт точный формат и старше по байтам; расхождение по смыслу считается дефектом спецификации, расхождение по формату исправляется в книге.
42. **Слово «ячейка».** «Ячейка» уже значит ячейку личности в Swarma Chain. *Рекомендация:* в книге писать «ячейка проекта» и «ячейка личности», всегда с определителем, пока владелец не утвердит словарь терминов.
43. **Название того, кто занимает место.** «Занимающий» владельцу не нравится. *Рекомендация:* до решения писать «агент на месте» и «занять место», без отдельного существительного.
